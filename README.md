# 全国教师公开招聘与备考助手（前端）

面向全国教师求职者的**公办教师公开招聘机会发现、资格匹配、报名推进与备考助手**：持续汇总官方公开招聘机会，按用户地域、学历、专业、毕业状态、教师资格和报考学科筛选可能符合的报考单元，逐项解释判断依据，跟踪报名节点，并在用户确定主要目标后生成备考计划。

> **学科开放范围**：产品长期面向各学科，**当前版本只开放语文学科**；语文是首个验证板块，不是产品长期边界。

产品需求的单一事实来源是根目录 [`PRD-全国教师公开招聘与备考助手-v6.1.md`](../PRD-全国教师公开招聘与备考助手-v6.1.md)（下称 **PRD v6.1**）。本 README 只描述前端仓库**当前实现了什么、计划迁移到什么状态**，不复写 PRD。

## 一、当前实现：v5.2 演示版（2026-10-04 现状）

> 状态标识：✅ = 仓库中已实现的演示能力（localStorage Mock）；🚧 = v6.1 目标，**尚未实现**，不得对外宣称完成。

当前仓库是一个**高完成度的可点击演示版，不是可正式运营的产品**：

- 业务数据全部保存在浏览器 `localStorage`（`kb_*` 键），没有真实后端持久化；
- 后端只有健康检查和 Prisma 骨架，详见 [`backend/README.md`](../backend/README.md)；
- 认证、AI 提取、文件上传、通知推送均为本地 Mock，代码中已标注真实替换点；
- 当前信息架构仍是 v5.2 的“**今天 / 接下来 7 天 / 我的考试**”，主线是“先确定考试目标，再回答今天做什么”——这与 PRD v6.1“机会发现在前、备考在后”的定位**不同**，将按[迁移计划](../docs/v6.1-migration-plan.md)改造。

### 技术栈

- Next.js 16.3.8（App Router）+ React 19.2.8 + TypeScript 5（strict）+ Tailwind CSS 4
- 数据：localStorage Mock（`kb_*` 键），服务层 + `useSyncExternalStore` 订阅
- 测试：Vitest 3 + jsdom
- 后端：NestJS 12 + Prisma 6 + PostgreSQL，当前仅 `/health` 可用
- 浏览器只调用同源 `/api/*`（[`src/app/api/[...path]/route.ts`](./src/app/api/%5B...path%5D/route.ts) 服务端反代，注入 `x-internal-token`）

### 快速开始

```bash
cd frontend
npm install
npm run dev        # http://localhost:3000
```

质量检查：

```bash
npm test           # Vitest，51 个用例（含境外依赖阻断守卫）
npm run check:external  # 扫描源码与构建产物的运行时外部依赖
npx tsc --noEmit   # 类型检查
npm run lint       # ESLint
npm run build      # 生产构建
```

后端联调（可选，当前仅健康检查）：

```bash
cd backend
docker compose up -d        # PostgreSQL（如已配置 compose）
npm install && npm run start:dev
# 健康检查地址默认 http://localhost:3000/health；现网部署端口由 PORT 环境变量决定
```

### 现有领域模块（迁移资产）

- `src/lib/guest/`：访客会话（7 天 TTL）、轻量结果引擎、登录迁移（幂等，带门禁）
- `src/lib/targets/`：v5.2 考试目标与门禁纯函数
- `src/lib/evidence/`：证据字段、提取器接口（`setExtractor` 接真实 AI）、证据服务与审核事件
- `src/lib/materials/`、`src/lib/resources/`：资料诊断与资源缺口匹配规则层
- `src/lib/plans/`：PlanEngine / ReplanEngine、反馈服务、今日任务（**v6.1 保留，后移到“主要目标”之后**）
- `src/lib/governance/`：纠错、撤回留痕、通知偏好、隐私删除
- `src/lib/analytics/`：19 事件 + 19 指标口径纯函数，seed/live 分开标记
- `src/lib/auth/`：`AuthService` 接口 + `DemoAuthProvider`（换真实认证只改 `instance.ts`）

### 关键架构约定（继续生效）

- 认证逻辑、用户状态、UI 三层分离；页面一律经 `useCurrentUser()` 取用户，路由保护用 `RequireAuth` / 角色判断。
- 领域规则集中在各模块 `domain.ts` 纯函数，页面只做展示与交互。
- AI 未审核结论永不标记“已从官方公告核对”；未支持的考试不生成伪精确计划。
- 正式（非 demo）状态不得静默回退到 Mock；演示数据必须明确标识。

## 二、v6.1 迁移目标（尚未实现）

PRD v6.1 的产品主线是：

```text
机会发现 → 可解释资格匹配 → 关注与报名日程 → 主要目标 → 备考
```

迁移完成后，用户端主导航只保留三个入口：

| 目标导航 | 回答的问题 | 主要内容 |
|---|---|---|
| 机会（`/opportunities`） | 现在有哪些值得我关注？ | 匹配结果、需补充的机会、搜索筛选、机会详情 |
| 日程（`/schedule`） | 接下来不能错过什么？ | 报名、审核、缴费、准考证、考试、结果节点 |
| 备考（`/study`） | 今天先做什么？ | 主要目标、能力基线、今日任务、反馈与调整 |

账号、画像、通知偏好、隐私与历史目标放在“我的/设置”，不占用主导航。首次使用为五组基础画像（地区、学历学位、专业、毕业与就业状态、教师资格），**未登录可看初步匹配结果，关注/保存/提醒时才要求登录**。

资格匹配必须支持四种结果：**初步符合 / 补充信息后判断 / 建议人工确认 / 明确不符合**；缺失信息永远不能被判定为不符合。公告事实、机器提取候选、人工审核结论必须分开存储与呈现。

路由、领域对象的新旧对应关系，以及每个模块的保留/改造/后移/暂缓处置，见 [`docs/v6.1-migration-plan.md`](../docs/v6.1-migration-plan.md)。
